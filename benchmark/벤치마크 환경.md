# 벤치마크 환경 (Benchmark Environment)

> 작성: 2026-11-12 · 대상: MAI / OpenClaw / Hermes Agent · 상태: **사전 설정, 실행 값 검증 전**

이 문서는 **이번 비교 실험에서 사용할 서버컴과 Gemma 4 12B 모델**을 기록한다. 대화에서 알려진 사양과 저장소 문서를 바탕으로 작성했으며, 실험 직전 재측정해야 하는 값은 '확인 필요'로 표시한다. [테스트 설계](%ED%85%8C%EC%8A%A4%ED%8A%B8%20%EC%84%A4%EA%B3%84.md)의 Track A 환경 정의로 사용한다.

## 1. 벤치마크 컴퓨터

| 항목 | 구성 |
|---|---|
| 역할 | MAI 서버/공통 로컬 LLM 추론 호스트 |
| 운영체제 | Windows 11 (정확한 빌드 확인 필요) |
| CPU | Intel Core i5-12400F |
| 시스템 RAM | 16GB |
| GPU | AMD Radeon RX 6800 XT |
| GPU VRAM | 16GB |
| 개발 쉘 | Git Bash 기본, 필요 시 PowerShell |
| 추론 엔진 | llama.cpp router (정확한 빌드/백엔드 확인 필요) |
| 모델 수 정책 | 동시 상주 모델 최대 1개 |
| 모델 저장 위치 | `portable/portable-models/gguf/` 아래 모델별 디렉터리 |
| 추가 스토리지 | 외장 USB HDD 사용 가능; 연결 해제 시 환경 오류로 분류 |
| 원격 워커 | 별도 노트북/워커 사용 가능. 실제 실험 전 연결 및 권한 확인 |

**참고:** CPU/RAM/GPU 용량은 알려진 서버컴 사양이다. 실행 당시 Windows 빌드, 드라이버, GPU 백엔드, 여유 RAM/VRAM, 발열 및 클럭은 자동 기록해야 한다. 모델 파일이 외장 USB에 존재할 경우 분리·절전·I/O 오류를 모델/에이전트 오류와 구별한다.

## 2. 고정할 언어 모델

| 항목 | 이번 실험 계획 |
|---|---|
| 모델 계열 | **Google Gemma 4** |
| 모델 | **Gemma 4 12B IT** (12 billion parameters) |
| 배포형식 | GGUF |
| 양자화 | **QAT Q4_0** |
| 저장소 문서의 파일명 예시 | `gemma-4-12b-it-qat-q4_0.gguf` |
| 비전용 projector 예시 | `mmproj-gemma-4-12b-it-qat-q4_0.gguf` (실제 파일/로더 호환성 확인) |
| upstream 출처 | [google/gemma-4-12B-it-qat-q4_0-gguf](https://huggingface.co/google/gemma-4-12B-it-qat-q4_0-gguf/tree/main) |
| 실제 모델 경로 | 실행 전에 확인할 것. 모델별 하위 디렉터리를 사용 |
| 모델 SHA-256 | **미측정 — 실행 전 기록 필수** |
| mmproj SHA-256 | 사용 시 측정. 파일이 없거나 과제에 불필요하면 '미사용' 기록 |
| Tool calling | MAI / OpenClaw / Hermes 각각 호환성 사전검증 필요 |
| 실험 대상 모델 동일성 | 세 에이전트가 **동일한 GGUF 파일과 llama.cpp 서비스**를 순차 사용 |

**Gemma 4 12B 사용을 명시적으로 선택한 실험 계획이다.** MAI의 일반 실행 기본 모델은 다른 GGUF일 수 있으므로, 벤치마크 설정에서 모델 ID를 별도로 선택·확인해야 한다. 이 문서의 파일명은 저장소 설치 문서에 있는 예시이며 실제 디스크에 존재한다고 단정하지 않는다.

## 3. 추론 및 자원 설정

| 항목 | 목표 또는 알려진 설정 | 주의 |
|---|---|---|
| 컨텍스트 | 목표 **65,536 토큰(64K)** | Gemma 4 12B 적재 가능 여부, 실제 런처의 값 확인 |
| GPU 메모리 예산 | `LLAMACPP_GPU_MEMORY_BUDGET_MIB=15360` (기존 정책 기준) | 최신 환경값 확인, 여유 VRAM 안전 조건 준수 |
| 최소 가용 RAM | `MAI_MIN_AVAILABLE_RAM_MIB=6144` (기존 정책 기준) | 물리 RAM 16GB와 함께 사전 로딩 검사 |
| 최소 여유 VRAM | `LLAMACPP_MIN_FREE_VRAM_MIB=1024` (기존 문서 기준) | GPU/백엔드 지원 여부 확인 |
| 모델 상주 | 1개 | 세 에이전트 동시 평가 금지 |
| Verifier | MAI **OFF** | 상대 구현에서 추가 검증 기능 사용 여부도 기록 |
| 개별 모델 호출 timeout | 기본 목표 500초 | **작업 전체 timeout과 다름** |
| 비교 작업 외부 제한 | 로컬 500초, 원격 1,000초 (설계안) | 작업 유형에 따라 충분한지 파일럿에서 검증 |
| 샘플링 | temperature/top-p/seed 등 동일하게 고정 | 실제 지원 옵션과 설정값을 manifest에 기록 |
| 네트워크 | 조사 과제 외에는 제한 | 클라우드 fallback 금지(Track A) |

**주의:** 64K 컨텍스트와 Gemma 4 12B를 16GB VRAM에 동시에 올릴 수 있다는 의미는 아니다. 특히 KV 캐시 및 vision projector 메모리가 추가로 필요할 수 있다. 모델 적재 실패는 **환경/호환성 문제**로 분리하며, 안전 가드를 끄거나 스왑을 강제해 결과를 만들지 않는다. 실제 실험 가능 컨텍스트 크기가 다르면 세 에이전트에서 같은 값으로 재설정한 뒤 계획에 변경 이력을 기록한다.

## 4. 재현성·실행 전 확인

- [ ] `./mai.sh check` 및 모델 카탈로그에서 Gemma 4 12B의 실제 파일 경로 확인
- [ ] 모델과 mmproj (사용 시) SHA-256 및 파일 크기 기록
- [ ] llama.cpp Git/릴리스/바이너리 버전·GPU 드라이버/백엔드·OS 빌드 기록
- [ ] 실제 컨텍스트 값, GPU layers, KV 캐시 양자화, 배치 크기, 샘플링 옵션 기록
- [ ] 안전 메모리 가드 유지한 채 단일 모델 정상 적재/도구 호출 성공 확인
- [ ] 서버 시작 전/후 및 과제 실행 중 RAM·VRAM 사용량 관측
- [ ] 외장 USB 저장장치 연결 안정성 및 디스크 사용 가능 여부 확인
- [ ] OpenClaw와 Hermes가 같은 API endpoint/model ID로 호출 가능한지 각각 점검
- [ ] 벤치마크용 VM/격리 계정·권한 제한, 개인정보·개인 DB 접근 차단 검증
- [ ] 버전 고정 결과를 실행 manifest에 저장(시크릿 제외)

### Windows PowerShell에서 참고용 확인 명령

```powershell
Get-CimInstance Win32_Processor | Select-Object Name
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory
Get-CimInstance Win32_VideoController | Select-Object Name, AdapterRAM, DriverVersion
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, BuildNumber
Get-FileHash "실제_모델_경로.gguf" -Algorithm SHA256
```

PowerShell의 GPU `AdapterRAM` 속성은 실제 가용 VRAM을 정확하게 나타내지 않을 수 있으므로 전용 GPU 모니터링 값으로 교차확인한다.

## 5. 결과 저장 원칙

각 실행의 `manifest.json`에 모델 파일 해시, 추론 엔진 버전, GPU/드라이버/백엔드, 컨텍스트, 메모리 가드, 에이전트 버전/설정, 작업·네트워크 권한을 기록한다. 작업 로그와 사용자·모델 입력은 민감정보를 제거하고, 벤치마크 결과/개인 데이터는 Git에 올리지 않는다.

실제 수치·결과가 확보되기 전에는 이 문서를 **확정된 실측 환경 보고서가 아닌 목표 실험 환경**으로 취급한다.
