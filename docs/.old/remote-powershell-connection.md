# MAI — Windows PowerShell / Linux shell 원격 연결

## 의도된 사용 흐름

1. 현장 PC의 브라우저로 MAI에 Owner 로그인.
2. 로그아웃 옆 **원격 연결**에서 일회용 세션을 생성하고 대상 OS에 맞는 Windows PowerShell 또는 Linux shell 시작 명령을 확인한다.
3. 제어 대상 PC의 해당 셸에서 명령을 실행한다. Linux는 Python 3.11+, `curl`, `unzip`, `sha256sum`, `python3 -m venv`와 필요한 OS 라이브러리가 준비되어야 한다.
4. 브라우저의 **원격 연결됨** 상태 확인 후 MAI에 해당 PC 작업 요청. 서버는 해당 Owner 계정의 활성 원격 세션을 결정함. 같은 PC 도구의 `is_remote=true` 호출이 그 PC에서 실행되며 생략 또는 `false`는 MAI 호스트에서 실행됨.
5. 원격 워커가 실행 중이고 서버로 주기적으로 폴링하는 동안 계속 사용. 원격 연결 버튼의 **연결 해제**는 서버 권한을 즉시 폐기.
6. 원격 워커 프로세스가 종료되면 새 명령을 받을 수 없음. 정상 종료 시 Agent가 서버에 세션 회수 요청. 비정상 종료/네트워크 중단 시 회수 요청이 실패할 수 있으므로 마지막 폴링부터 최대 약 180초가 지나면 서버가 해당 세션을 유효하지 않게 판정함.

## 제한

- 새로 발급한 명령을 **최초 실행하기 전**의 유효기간은 10분. 연결 후 폴링·결과는 180초 연결 상태 확인에 사용한다. 별도의 **10시간 실제 작업 유휴 기한**은 원격 작업 요청이나 인증된 작업 결과에 의해 갱신되며, 단순 폴링만으로 갱신되지 않는다.
- 명령에 임시 인증 키가 포함되므로 PowerShell 기록, 클립보드 이력 또는 화면 공유를 통해 유출될 수 있음. 사용 후 명령/키를 다른 사람에게 공유하지 말 것.
- **PowerShell 종료는 신규 원격 작업을 막지만**, 이미 시작된 외부 프로세스가 항상 강제 종료된다고 보장하지 못함. 이 부분은 추가 구현 및 Windows 종단간 검증이 필요함.
- 브라우저만으로 OS를 관리할 수 없으므로 원격 대상에서 PowerShell 또는 Linux shell 시작 명령을 직접 실행해야 함.
- HTTPS와 MAI Owner 로그인을 요구하며 Agent는 관리자 권한으로 자동 상승하지 않음. 기기 소유자 또는 조직의 허가 범위에서 사용.
- 다른 PC에서 실사용하기 전 본인 소유 테스트 PC에서 일반 사용자 권한으로 검증 필요.

## 현재 도구 계약

Owner의 원격 지원 native 도구(파일·코드·CSV·문서 편집·터미널·웹·브라우저·계산·시간·시장 정보 등)는 로컬과 같은 입력에 `is_remote` boolean을 추가함. 모델이 원격 세션 ID를 직접 지정하지 않으며, 연결이 없거나 끊어졌을 때 로컬 실행으로 전환하지 않음. `memory_search`, `tool_result_read`, `file_download_link`는 서버 내부 상태에 종속되어 원격화되지 않는다. `image_analyze`는 폐기했으며, 이미지 입력은 서버의 메인 GGUF가 지원할 때만 사용한다.

메인 프롬프트는 첫 턴부터 원격 연결과 실행 대상 선택을 안내함. 원격 PC 작업은 탐색·조회·수정·실행·결과 확인까지 해당 도구 호출마다 `is_remote=true`를 지정함. 브라우저 접속 기기나 도구 활성화만으로 실행 대상이 바뀌지 않으며, 호스트 경로·작업 폴더·셸을 원격 PC 정보로 간주하지 않음. 도구별 상세 문맥은 활성화 후 제공함.

구현은 `mai/remote/routing.py`, `mai/remote/target.py`, `mai/remote/python_worker.py`, `mai/app/static/remote-agent.ps1`, `mai/app/static/remote-agent-linux.sh`를 기준으로 함. 이전 별도 `remote_file_*` 등록 helper는 소스에 남아 있지만 현재 production registry에서 호출하지 않음.
