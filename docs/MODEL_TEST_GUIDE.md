# Mai Fresh-DB Model Test Guide

이 문서는 Mai의 DB를 초기화한 뒤, 실제 모델이 핵심 계약과 기능을 순서대로 수행하는지 수동으로 확인하기 위한 테스트 가이드다.

테스트를 시작하기 전 Mai 서버를 정상 종료한 뒤 필요한 DB를 초기화하고 다시 실행한다. 각 항목은 가능한 한 아래 순서대로 진행한다.

## 1. 기본 JSON 계약 유지 확인

사용자 입력:

```text
안녕?
```

확인 목적:

- 평범한 대화에서 파일/터미널 같은 불필요한 tool로 빠지지 않는지 확인한다.
- 최종 사용자 응답이 정상적인 answer 경로로 반환되는지 확인한다.

## 2. 장기기억 저장 확인

사용자 입력:

```text
우선 통성명부터 할까? 나는 신재용 이라고 해. 성은 신, 이름은 재용 이야.
```

확인 목적:

- 사용자에 대한 장기 semantic memory가 생성되는지 확인한다.
- 이후 8번 회상 테스트를 위한 기억을 만든다.

## 3. 파일 읽기 툴 확인

사용자 입력:

```text
나는 현재 sllm 관련 프로젝트를 진행하고 있어. 현재 너의 루트가 바로 그 프로젝트인데, 네 루트의 readme.md를 읽어보고, 너가 이해한 대로 설명을 한번 해볼래?
```

확인 목적:

- 현재 working root를 기준으로 파일을 발견할 수 있는지 확인한다.
- 필요한 tool manual을 확인한 뒤 README를 실제로 읽는지 확인한다.
- 읽지 않은 내용을 추측하지 않고 실제 파일 내용에 근거해 설명하는지 확인한다.

## 4. 모델 계약 인지 여부 확인

사용자 입력:

```text
좋아. 이 프로젝트에 대한 대략적인 이해는 어느정도 잘 한거 같아. 그럼 이제 너가 사용 가능한 툴을 전부 나열해 줄 수 있을까?
```

확인 목적:

- 모델이 현재 노출된 compact tool catalog와 built-in capability를 이해하는지 확인한다.
- 존재하지 않는 tool을 임의로 만들어내지 않는지 확인한다.

## 5. 증시 검색 툴 확인

사용자 입력:

```text
현재 삼성전자의 시가총액과 주가, PER을 알려줘.
```

확인 목적:

- 현재 시장 정보가 필요한 요청에서 market/web capability를 적절히 사용하는지 확인한다.
- 조회 결과를 근거로 답하는지 확인한다.

## 6. 일반 검색 툴 확인

사용자 입력:

```text
좀 뜬금없긴 한데, 총기시장에서 글록이 의미하는 바와, 글록의 가장 두드러지는 특징들을 2개 정도 말해볼래?
```

확인 목적:

- 일반적인 외부 정보 요청에서 web search/research capability를 사용할 수 있는지 확인한다.
- 검색 근거와 답변이 연결되는지 확인한다.

## 7. 필요한 경우 정정 후 서버 종료

앞 단계에서 명백히 틀린 답이나 잘못 저장된 정보가 있다면 정정 메시지를 보낸다.

그 다음 Mai 서버를 정상 종료한다.

```text
Ctrl+C
```

확인 목적:

- 정정이 필요한 경우 장기기억 수정 흐름을 거칠 수 있는지 확인한다.
- 재실행 후에도 장기기억이 유지되는지 확인하기 위해 서버 프로세스를 한 번 종료한다.

## 8. 장기기억 회상 확인

Mai를 다시 실행한 뒤 사용자 입력:

```text
안녕? 나에 대해 어디까지 기억하니? 기억하는 바를 모두 말해볼래?
```

확인 목적:

- 재실행 이후에도 SQLite의 장기기억이 유지되는지 확인한다.
- 2번에서 저장한 사용자 정보와 테스트 중 장기적으로 저장된 정보가 실제 graph recall을 통해 회상되는지 확인한다.
- 현재 raw 대화 context만으로 답하는 것이 아니라, 필요한 경우 durable memory를 조회하는지 확인한다.
