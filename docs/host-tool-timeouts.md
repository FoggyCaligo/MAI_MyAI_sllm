# 호스트 도구 타임아웃 기준

2026-11-09 변경: 호스트 컴퓨터에서 실행하는 도구의 기본 제한 시간을 두 배로 확대한다. 파일·CSV·코드·문서 작업은 60→120초, 터미널의 실제 프로세스 실행은 120→240초, 계산·시간 조회는 10→20초, 웹 검색·조회·시장 조회는 30→60초, 브라우저 도구들은 각 기존 제한의 두 배로 동작한다.

호스트 `terminal_run`은 `ToolDefinition.timeout_seconds=None`이며 별도 터미널 핸들러 내부의 실행 제한을 사용하므로 이를 240초로 변경했다. 원격 워커는 이미 기존 기본값의 두 배를 적용하고 있으므로, 호스트 기본값을 다시 원격에서 곱하지 않도록 원격 워커의 파일·코드 기본 기준값은 기존 60초를 명시하고 독립적으로 두 배 적용한다. 원격 터미널은 워커 등록 시 실행 제한 480초를 지정한다. 서버 원격 전송 대기는 600초이며, 메타데이터상의 제한과 내부 실행 제한의 이중 배수 적용 여부는 별도로 점검할 필요가 있다.

현재 기준 `settings.yaml`의 모델 요청 제한은 **300초**이며, 이 값은 각 llama.cpp 모델 요청에 적용되고 사용자 요청 전체의 300초 상한은 아니다. 원격 전송 결과 대기 상한은 **600초**다. 원격 터미널 실행 제한의 실제 워커 내부 값은 480초(`terminal_timeout_seconds=240 * 2`)이며, 등록된 도구 정의의 타임아웃 메타데이터에는 추가 배수가 적용된다. 실행 제한과 전송 대기를 하나의 값으로 혼동하지 않는다. 세션 연결·유휴 기간은 별도다. 타임아웃·명령 오류는 그대로 실패로 드러나며, 호스트·원격 간 자동 대체는 하지 않는다.

감사 DB `log(20261109-014400).sqlite3`에서 호스트 `terminal_run`이 약 120초 후 `TerminalTimeoutError`로 두 번 실패한 것을 확인했다. 명령 중 Windows CMD에서 지원하지 않는 Unix 명령을 혼용한 문제는 별도 개선 대상으로 남겨 두며, 이번 시간 확대만으로 해결됐다고 판단하지 않는다.
