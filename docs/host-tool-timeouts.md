# 호스트·원격 도구와 모델 요청의 타임아웃

현재 `dev` 코드를 기준으로 하며, 설정값·도구 내부 실행 제한·원격 전송 대기는 **서로 다른 계약**이다.

| 대상 | 한도·근거 |
|---|---|
| Main/Verifier 등 llama.cpp 모델 API의 개별 요청 | 기본 **300초**. `settings.yaml: MODEL_REQUEST_TIMEOUT_SECONDS` 및 `mai/llm/models.py` |
| 로컬 파일·코드·CSV·문서 도구 | 기본 **120초** |
| 로컬 `terminal_run`의 실제 셸 프로세스 | 기본 **240초**. `mai/tools/terminal.py`의 내부 실행 제한 |
| 로컬 계산·시간 | 기본 **20초** |
| 로컬 웹 검색·조회·시장 조회 | 기본 **60초** |
| 원격 파일·코드 도구 | 현재 워커 구현은 **240초**. `mai/remote/python_worker.py`에서 120초 등록 뒤 2배 적용 |
| 원격 `terminal_run`의 실제 셸 프로세스 | **480초**. 워커에서 `240 * 2` 지정. `terminal_run`의 등록 타임아웃은 `None`이며 별도의 내부 제한을 사용 |
| 원격 전송 결과 대기 | **600초**. `mai/remote/session.py` |
| GAIA 한 문제당 평가 실행기 기본 제한 | **1,800초**. `benchmark/GAIA Benchmark/adapter/run_gaia.py` |

브라우저 도구는 고정 단일 값이 아니라 각 API마다 다르다. 워커 등록 시 `timeout_multiplier=2`를 적용하고 원격 레지스트리 등록 과정에서 타임아웃에 다시 2를 곱하므로 **현재 원격 브라우저 등록 제한은 로컬 등록 제한의 4배**다. 웹·시장 정보 도구는 워커 등록 60초에 다시 2배를 적용한다. 일반적으로 모든 원격 도구가 로컬 도구의 정확히 2배라고 단정하면 안 된다.

모델 요청의 300초는 **사용자의 한 번의 전체 대화 처리 한도**가 아니다. 여러 Main 호출·도구 실행·Verifier 호출이 있는 요청은 전체 소요 시간이 300초를 넘을 수 있다. GAIA의 1,800초도 모델의 300초 제한을 자동 연장하지 않는다.

시간 초과나 잘못된 셸 명령은 그대로 오류로 드러나야 한다. 원격 도구가 실패해도 MAI 호스트에서 대신 실행하지 않는다. 실제 타임아웃과 문서 정책이 다르게 동작하면 임의 우회하지 말고 각각의 실행 단계 및 감사 로그를 확인한다.
