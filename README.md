# 개인 컴퓨터 관리용 범용 로컬 LLM 에이전트

**사용법: [setup.md — 설치부터 실행까지](setup.md)**

MAI는 본인의 개인 컴퓨터에서 실행되어 해당 컴퓨터 전반을 관리하는 인공지능 비서이다. 대화만 하는 것이 아니라, 사용자가 허용한 범위에서 웹을 검색하고, 문서를 읽고, 파일과 코드를 다루고, 터미널 명령도 실행할 수 있다. 답변 생성에는 **Ollama로 실행하는 로컬 언어 모델**을 사용한다.

> 파일 수정·삭제와 터미널 실행은 실제 컴퓨터에 영향을 줄 수 있으니, 중요한 파일은 미리 백업하고, 외부 접속을 설정하기 전에는 계정과 공개 범위를 확인해야 함.

## 1. 주요 기능

| 기능 | 무엇을 할 수 있나? |
|---|---|
| **장기기억** | 대화에서 오래 참고할 만한 사실을 별도 저장소에 기록하고, 다음 대화에서 찾아 활용함. |
| **문맥 유지** | 최근 대화 내용을 이어받아 후속 질문에 답하며. 장기기억과는 별도로 대화 기록을 관리함. |
| **웹 검색** | 인터넷 검색, 웹페이지 본문 읽기, 자바스크립트로 표시되는 페이지의 버튼·페이지 이동 등을 지원함. |
| **증권정보 검색** | 증권시장 정보 조회 도구를 사용해 종목 관련 데이터를 확인할 수 있으며, 조회 가능한 항목은 연결된 정보 제공처에 따라 달라짐. |
| **파일 구조 확인** | 폴더와 하위 폴더 목록, 파일 이름·크기·수정 시각, 파일 이름 검색 등을 지원함. |
| **파일 읽기·관리** | 일반 텍스트와 주요 문서를 읽고, 파일 생성·내용 쓰기·삭제·이동·복사를 수행함. |
| **문서 편집 (`document_edit`)** | 기존 DOCX 문단·표 셀, XLSX 셀, PPTX 도형 텍스트, CSV 셀을 수정하고 PDF 페이지를 회전·삭제함. 소유자 계정 전용. |
| **코드 확인·관리** | 소스코드 검색, 지정한 줄 읽기, Python·JavaScript·TypeScript·TSX·C·C++·Java·Go·Rust·Ruby의 함수 및 타입 구조 분석을 지원함. 코드 수정·생성·삭제는 파일 도구 또는 터미널을 이용함. |
| **터미널 사용** | 프로그램 실행, 명령어 실행, 설치·검사 등 로컬 컴퓨터 작업을 수행할 수 있음. |
| **이미지 인식** | 이미지 모델 `gemma4:e4b`를 `VISION_MODEL`에 지정해 사진이나 그림을 분석함. 해당 모델을 설치·설정하지 않으면 이용할 수 없음. |
| **음성 대화** | 목소리 등록·화자 비교, 음성을 글로 바꾸는 기능, 음성 모드에서 답변을 소리로 읽는 기능을 제공함. 음성 답변은 브라우저의 음성 합성 기능을 사용함. |
| **외부 접속용 사이트** | Tailscale Funnel을 설정하면 다른 기기에서도 웹주소로 접속할 수 있어. **Tailscale 설치·로그인·설정이 별도로 필요해.** |
| **원격 파일 다운로드 링크** | 외부에서 사이트로 MAI 사용 시, 해당 PC 내부의 데이터를 해당 사이트에서 다운받을 수 있는 링크 생성 기능을 지원함. 접근 권한과 서버 실행 상태에 영향을 받음. |

### 도구 호출 방식

MAI는 매번 모든 도구의 상세 입력 스키마를 모델에 넣지 않음. 먼저 사용 가능한 도구의 이름과 분류를 간략히 전달하고, 모델이 `tool_manual`로 필요한 도구를 활성화하면 다음 추론 단계부터 해당 도구의 Native Tool Schema를 제공함. 한 작업에서 이미 활성화한 도구는 재활성화 없이 계속 사용할 수 있음.

### 지원 파일 형식

**문서 내용을 구조적으로 읽는 형식**은 다음과 같음.

| 확장자 | 파일 종류 | 읽기 방식 |
|---|---|---|
| `.pdf` | PDF 문서 | 각 페이지의 텍스트 추출 |
| `.docx` | 워드 문서 | 문단과 표 읽기 |
| `.xlsx` | 엑셀 문서 | 시트와 셀 값 읽기 |
| `.csv` | 쉼표로 구분한 표 | 행과 열을 구분해 읽기 |
| `.pptx` | 발표 자료 | 슬라이드 안의 글자 읽기 |

**일반 텍스트로 읽고 쓰는 형식**에는 `.txt`, `.md`, `.log`, `.json`, `.jsonl`, `.yaml`, `.yml`, `.toml`, `.ini`, `.cfg`, `.xml`, `.html`, `.htm`, `.css`, `.js`, `.ts`, `.py`, `.sh`, `.ps1`, `.bat`, `.sql`, `.c`, `.h`, `.cpp`, `.hpp`, `.java`, `.go`, `.rs`, `.rb` 등이 있음.

이 목록은 **텍스트로 저장된 파일의 예시**임. 확장자가 같더라도 파일 내용이 실제로 텍스트여야 하고, 문자 인코딩·권한에 따라 읽지 못할 수 있음. 텍스트 파일은 확장자에 관계없이 읽을 수 있는 경우가 많지만, 이미지·영상·압축파일처럼 바이너리 형식인 경우 일반 텍스트 읽기로 처리하지 않음.

파일 **관리**(생성·내용 쓰기·삭제·이동·복사)는 확장자 자체에 크게 제한받지 않음. 기존 구조화 문서에는 `document_edit` 툴로 지정 위치를 수정할 수 있음.

| 형식 | `document_edit` 작업 | 한계 |
|---|---|---|
| DOCX | 최상위 문단 텍스트, 표 셀 내용 변경 | 문단 텍스트 전체 대체 시 문자별 서식이 초기화될 수 있음 |
| XLSX | 시트 이름·셀 주소를 지정하여 값/수식 변경 | 셀 범위 일괄 수정 및 차트 구조 편집 미지원 |
| PPTX | 슬라이드·도형 인덱스를 지정한 텍스트 변경 | 텍스트 대체 시 해당 도형의 부분 서식이 초기화될 수 있음 |
| PDF | 페이지 회전·삭제 | PDF 본문 텍스트 직접 수정 미지원 |
| CSV | 기존 행·열 셀 값 변경 | 셀 추가·행 확장 미지원 |

`document_edit`는 **새 문서를 생성하지 않으며**, 기존 문서만 처리함. 인덱스는 모두 1부터 시작하고 대상이 없으면 명시적으로 실패함. `output_path`를 지정하면 원본을 보존하여 별도 파일로 출력 가능하며, 생략하면 원본을 수정함. 저장은 임시 파일 생성 후 교체하는 방식임. 기존 `python-docx`, `openpyxl`, `python-pptx`, `pypdf`를 사용하므로 **추가 패키지 설치는 필요하지 않음**.

코드 검색·읽기는 여러 텍스트 기반 프로그래밍 언어에 사용할 수 있지만, **코드의 함수·클래스 구조를 자동 분석하는 전용 기능은 현재 파이썬 코드에 한정**됨.

## 2. 장기기억의 구조와 원리

MAI는 기억을 매번 긴 문장으로 모델에 집어넣지 않고, 컴퓨터 안의 **그래프 형태 저장소**에 기록함. 그래프는 **노드(점)**와 **에지(연결선)**로 이루어져 있음.

### 그래프 구조

```text
[사용자 기준점]
       │ 사실을 기억함
       ▼
 [사실 노드] ── 관련 개념 ──▶ [개념 노드]
```

- **사용자 기준점 노드:** 누구에 관한 기억인지 구별하는 출발점.
- **사실 노드:** 대화에서 확인한 지속적으로 참고할 만한 정보를 담음.
- **개념 노드:** 비슷한 내용의 기억을 찾기 위한 검색 단서.
- **에지:** 사용자와 사실, 사실과 개념 사이의 관계를 나타냄.

대화의 **원문은 별도 근거 기록**으로 보존함. 원문 하나마다 새로운 그래프 노드를 무한히 만드는 방식은 아님.

### 기억은 어떻게 저장할까?

1. 대화가 끝난 뒤, **로컬 언어 모델이 기억할 만한 사실을 추출**함.
2. 추출된 사실을 저장할 때 **([Sentence Breaker](https://github.com/FoggyCaligo/Sentence_Breaker)) 등의 알고리즘**으로 검색용 개념을 정리함.
3. 사실과 개념을 그래프에 연결하고, 원래 사용자 발화는 별도 근거 기록에 남김.

즉, **사실 추출에는 LLM을 사용하지만 그래프 구성·개념 색인에는 별도의 알고리즘을 사용**함.

### 기억은 어떻게 다시 찾을까?

1. 모델이 지금 필요한 기억을 질문 형태로 조회.
2. 검색어를 공백 기준으로 나누고, 저장된 개념 색인에서 **정확 일치 및 SQLite 전문 검색(FTS5)**으로 후보를 찾음.
3. 연결된 사실 노드를 가져와 답변에 참고함.

검색할 때마다 과거 대화를 전부 모델에 다시 넣는 방식이 아님. **개념을 통해 필요한 사실만 골라 가져오는 구조**이고, 저장소의 주요 데이터는 `data/memory.sqlite3`에 있음. 별도의 임베딩·벡터 검색 공간을 핵심 식별 체계로 사용하지 않아, 임베딩 모델을 바꿀 수 없다는 기존 벡터 DB의 제약으로부터 자유로움. 

최근 대화 문맥은 `data/chat.sqlite3`, 문제 확인용 실행 기록은 `data/log.sqlite3`로 구분해 관리함.

더 자세한 구조는 [기억 구조 문서](WORKING_CONTRACT.md)를 참고.

## 3. 처음 설치하는 방법

**Windows 10/11**이라면 관리자 권한으로 **PowerShell**을 열고 아래 명령을 **한 번에 붙여넣어** 실행.

```powershell
$installer = Join-Path $env:TEMP 'mai_install_windows.ps1'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/FoggyCaligo/MAI_MyAI_sllm/dev/scripts/install_windows.ps1' -OutFile $installer
powershell -NoProfile -ExecutionPolicy Bypass -File $installer
```

이 설치 과정은 Git·Python·Ollama 등의 설치 상태를 확인하고, MAI 다운로드, 가상환경과 필요한 라이브러리 설치, 웹 브라우저 실행 구성요소 설치까지 진행함. 사용자 계정 비밀번호와 사용할 모델 이름 등은 설치 도중 직접 입력해야 함.

**설치 명령은 인터넷에서 스크립트를 내려받아 실행하므로**, 실행 전에 [설치 스크립트 내용](scripts/install_windows.ps1)을 확인하는 걸 권장함. 기존 `.env`와 기억·대화 데이터는 덮어쓰지 않도록 구성돼 있음. 실제 Windows 환경에서는 설치된 프로그램과 설정에 따라 추가 조치가 필요할 수 있음.

Tailscale을 통한 외부 접속은 자동으로 공개하지 않음. 외부 접속 설정, 계정 관리, 오류 해결까지 포함한 자세한 안내는 **[setup.md](setup.md)**에서 볼 수 있음.

## 4. 이후 실행하는 방법

설치를 끝냈다면 일반 권한의 터미널을 열어 MAI 폴더에서 실행하면 됨.

```bash
python run_server.py
```

Windows에서 처음 설치한 뒤에는 필요하면 먼저 프로젝트 폴더로 이동하고 가상환경을 켜야 함.

```powershell
cd "$env:USERPROFILE\Documents\Git\MAI_MyAI_sllm"
.\.venv\Scripts\Activate.ps1
python run_server.py
```

서버가 실행되면 같은 컴퓨터의 브라우저에서 **http://127.0.0.1:8000**에 접속하면 됨. 외부 접속은 Tailscale Funnel을 별도로 설정한 경우에만 가능.

문제가 발생하면 **[설치·실행·오류 해결 안내서](setup.md)**를 확인.
